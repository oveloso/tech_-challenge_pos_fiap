FALHA OBSERVADA
docker desktop start --detach iniciou o aplicativo, mas o backend encerrou antes
da criação do pipe dockerDesktopLinuxEngine. O log registrou:

  starting services: initializing Inference manager:
  listening on unix://<LOCALAPPDATA>/Docker/run/dockerInference:
  remove .../dockerInference: The file cannot be accessed by the system.

O objeto era um socket AF_UNIX vazio (Archive, ReparsePoint). Com o Docker parado
pelo comando oficial docker desktop stop --force --timeout 15, a pasta contendo
somente sockets temporários foi preservada por renomeação; não houve exclusão.
Após recriar a pasta vazia, a inicialização avançou e encontrou a mesma falha em
<LOCALAPPDATA>/docker-secrets-engine/engine.sock. Essa pasta continha somente esse
socket vazio e também foi preservada. A nova tentativa chegou à inicialização WSL,
mas o processo reiniciou e voltou à falha do socket dockerInference.

Pastas temporárias preservadas no computador, fora do repositório:
- <LOCALAPPDATA>/Docker/run-preservado-fiap-20261029
- <LOCALAPPDATA>/Docker/run-preservado-fiap-20261029-2
- <LOCALAPPDATA>/docker-secrets-engine-preservado-fiap-20261029

O comando oficial de parada confirmou a interrupção do Docker Desktop. Na checagem
seguinte surgiram novos processos Desktop/backend; a causa desse reinício não foi

Não houve reset, reinstalação, limpeza de imagens/volumes, exclusão de VHDX, alteração
